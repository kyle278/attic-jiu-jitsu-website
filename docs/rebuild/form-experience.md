# Attic enquiry journey and field decisions

User explicitly requested the form-experience skill during implementation. Read its SKILL.md and implementation/research references. This supersedes the earlier contact-first two-step proposal, without adding a third peer-design cycle. Outcome: a useful enquiry so the academy can help choose a class/membership. It does not reserve, buy or book anything. Email response is disclosed on the first screen.

| ID | Purpose / action enabled | Decision | Required | Control / visibility | Advance / validation | Destination |
| --- | --- | --- | --- | --- | --- | --- |
| Training interest | Route the conversation to beginner, experienced adult, youth or general/membership help | Add; replaces needing to invent the right terminology in free text | Yes | Four SVG answer-and-continue buttons, first screen | Deliberate activation only; synchronously committed step guard, repeated keys/double-click guard | Visible editable prefix in existing message field |
| First name | Address the reply and identify the person enquiring | Keep separate | Yes | Native given-name input, details screen | Explicit Continue; nonempty, names accept accents/apostrophes/single characters | first_name |
| Last name | Identify the person and match follow-up | Keep separate under established contract | Yes | Native family-name input | Explicit Continue; nonempty | last_name |
| Email | Deliver the promised reply | Keep | Yes | Native email input with use explanation | Explicit Continue and final check; valid email | email |
| Phone | Alternative contact if the sender wants the academy to call about this enquiry | Keep optional; collapse to reduce visual load | No | Native tel input inside optional disclosure | No automatic advance; normal international formatting accepted | phone |
| Message | Ask a specific question and retain selected published plan/context | Keep optional, editable | No | Native textarea; intent and plan prompt visible | Never overwrite user text; Back preserves DOM values | message |
| Privacy / response permission | Acknowledge new policy and authorise response | Keep existing name, revise presentation | Yes | Full clickable native-checkbox card on final screen; independent working policy link opens new tab | Explicit final submit | privacy_consent |
| Accuracy confirmation | Established independent declaration in the integration | Keep; no backend validator change authorised | Yes | Compact associated native label on final screen | Explicit final submit | accuracy_confirmation |
| Academy email updates | Purpose-specific optional marketing permission | Keep, separate from service response | No | Separate full clickable native-checkbox card, initially unchecked | Never advances; absence permits service enquiry | marketing_consent |
| Campaign fields / submission URL | Attribute a successful enquiry to its source and preserve browse context | Keep whitelist and names | Automatic | Hidden, no contact/draft persistence | Current URL wins over tab session campaign values | Existing utm_* casing, CID, Submission URL |

All screens remain mounted and inactive screens are hidden from focus/accessibility. Explicit validation reveals the correct screen before focusing an error. Contact details stay near the end. No extra review or repeated answer-summary stage. Parent guidance asks for the adult’s details, not a child’s identity. All choices are meaningful text and simple inline SVG, with no emojis or decorative navigation arrows. Each final consent checkbox operates independently; policy link neither toggles acceptance nor loses answers. Success is shown only in response to the established portal success event.

The user authorised a new privacy page. It uses verified business contact details and observable website behaviours. Source guidance: [Irish DPC transparency](https://www.dataprotection.ie/en/individuals/know-your-rights/right-be-informed-transparency-article-13-14-gdpr) and [retention principles](https://www.dataprotection.ie/en/faqs/responsibilities-data-controllers/how-long-should-personal-data-be-held-meet-obligations-imposed-gdpr). No fixed retention duration, legal corporate identity, processor geography or international safeguard was invented. Those operational details need the academy’s confirmation before publication; the local rebuild does not deploy or certify legal compliance.

Verification must cover every intent, Back/edit, repeated activation, reduced motion, short mobile viewport, required privacy versus optional marketing, independent policy link, separate names, invalid email, full FormData at final step, hidden-field revalidation, failed/retried submission and real success event handling in an isolated mocked browser. No production lead is sent.
