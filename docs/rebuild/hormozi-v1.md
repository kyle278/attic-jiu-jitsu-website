# Attic build plan v1: make the first step clear

Owner: Hormozi agent. References: `research.md`, existing public site source and published catalogue, and research of live atticbjj.net. The Offers and Leads skills supply the planning method, not alternative brands, visual references or copy. Public marketing only. This document proposes a website, not new business terms, an ad launch or a change to booking.

## Strategic choice

The primary conversion problem visible in the project is uncertainty: a visitor sees inclusive language but still has to work out which session is appropriate, what beginning costs, whether equipment is needed and what pressing a button actually does. Stronger proof and a concrete starter offer can answer that. No analytics establish a conversion failure, so this is an expert hypothesis, not a measured diagnosis.

Positioning: **Serious jiu jitsu. A place to start.** Support: **Brazilian jiu jitsu in Carlow. Adults, kids and teens. Complete beginners welcome.** Make the first-visit path concrete without implying instant fitness, guaranteed confidence, a free trial or a reserved place. Repeat one primary action, **Start training**, which always leads to the existing enquiry form. Secondary **View timetable** leads to `/classes#live-schedule`. Members always have a plain **Members** link to `/members`.

Offer hierarchy: adult beginner programme as the home page's concrete example; parents get an equally visible audience route; experienced visitors can go directly to schedule and memberships. Do not force an experienced member through beginner sales copy. Keep the actual published plan names and contents on membership cards. Use a benefit heading above the catalogue item rather than rename the item itself.

## Visual system and layout

Keep Barlow Condensed display and Source Sans 3 body from the project. Preserve Attic red `#c43148`, ink `#0f0c0d`, chalk `#f7f3f1`. Use a darker red only where required for text contrast, verifying actual computed combinations. Red identifies action, selection and the Attic mark. No gradients, fluorescent accents, decorative pricing strike-throughs or luminous panels. Photography remains authentic and mainly monochrome; preserve visible photographer credit in crops or add the exact existing credit beneath the image if an uncropped display is necessary.

Composition: a wide dark photo opener, a light editorial programme section, a red edge/ink starter panel, a calm light coach section, a dark image story and light practical first-visit information. This rhythm avoids a wall of dark bordered cards. Sharp corners and thin rules evoke mat edges and belt stripes; do not decorate every item with a card. Use a shared desktop container around 1240px, 64px side gutters at large widths, reducing to 24px tablet and 20px mobile. Proposed layout values are implementation specifications, not business facts.

Display sizing: `clamp(3.25rem, 7.5vw, 7.5rem)` on the home headline, max 12 characters per deliberately authored line where possible. Supporting prose remains 18–20px with 1.55–1.65 line height and a 60-character measure. Inner page titles use a smaller 48–88px range. Never hard-code a headline width wider than its grid track. Body text is sentence case. Section titles can use condensed uppercase; prices and phone numbers use tabular numerals where available.

Header: logo at left, Classes / Memberships / About / Gallery navigation, Members as a quiet separate utility, Start training as the sole filled action. Header initially sits on solid ink for readable navigation, sticky at 72px desktop / 64px mobile. Mobile has logo, Members text link and a Menu button; the menu reveals a conventional vertical navigation below the header, not a full-screen theatrical scene. Menu exposes `aria-expanded`, closes with Escape and route change, restores focus, and does not trap the user in navigation. Skip-to-content link precedes it.

## Motion specification

Motion expresses movement with control and never implies loading the business service. One hero choreography: logo/header fade 200ms; two headline lines reveal with translateY 18px to 0 and opacity over 600ms, stagger 90ms; body/actions over 350ms after 120ms; hero image scale 1.035 to 1 over 850ms. Total perceived opening under 900ms. Use progressive enhancement: content is readable in SSR and if controller fails; never `opacity:0` as the permanent baseline. Title remains a single semantic h1 with visual spans, not character splitting read by screen readers.

Desktop only, fine pointer, reduced-motion false: one training-life image moves from translateY 18px to -18px over that section's natural scroll; no pinning, scroll hijack, forced snap or page-height inflation. Mobile shows a static composition. Implement with a small isolated controller using requestAnimationFrame, passive listeners, IntersectionObserver and cleanup; prefer supported CSS scroll animation with a safe fallback if lower effort. No 3D library, canvas hero, smooth-scroll dependency, custom cursor or autoplay media.

Buttons: 180ms background/border/arrow translation 3px; focus equivalent without transform dependency. Programme rows: 180ms underline/arrow; no giant image reveal covering text. Mobile menu: 200ms opacity + 8px translation, content not height-measured every frame. FAQ: immediate native opening, optional 180ms chevron rotate only. Gallery modal: 160ms fade; image changes without sliding disorientation. Initial image layout uses known ratios to avoid CLS. No generic fade-up on all sections and no mandatory animation for prices/times/forms.

Reduced-motion: all transforms and scrolling scenes disabled, menu and modal state changes immediate or <=100ms opacity, normal anchor scroll. Disable scroll scenes when tab hidden and never install them at narrow widths. Verify preference change is handled at runtime if using JS.
